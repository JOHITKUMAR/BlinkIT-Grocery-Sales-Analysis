# BlinkIT Grocery Sales Analysis 

## 📌 Project Overview
This project analyzes grocery sales data for **BlinkIT** ("India's Last Minute App") using Power BI. It combines a raw sales dataset (`BlinkIT_Grocery_Data.xlsx`) with an interactive dashboard that breaks down sales performance by item, outlet, and location attributes.

---

## 📂 Files in This Project
| File | Description |
|---|---|
| `BlinkIT_Grocery_Data.xlsx` | Raw transactional/item-level dataset used to build the dashboard |
| Dashboard screenshot | Power BI report visualizing the dataset (see below) |

---

## 🗂️ Dataset Structure
The dataset contains **8,523 rows** and **12 columns**, each row representing one item sold at a specific outlet.

| Column | Type | Description |
|---|---|---|
| `Item Identifier` | Text | Unique ID for each item (e.g., FDX32) |
| `Item Fat Content` | Text | Fat category of the item — values are inconsistent (`Regular`, `Low Fat`, `low fat`, `LF`, `reg`) and should be standardized during cleaning |
| `Item Type` | Text | Product category (Fruits & Vegetables, Snack Foods, Household, Frozen Foods, Dairy, Canned, Baking Goods, Health & Hygiene, Meat, Soft Drinks, Breads, Hard Drinks, Others, Starchy Foods, Breakfast, Seafood) |
| `Item Weight` | Numeric | Weight of the item |
| `Item Visibility` | Numeric | Percentage of total display area allocated to the item in the store |
| `Outlet Identifier` | Text | Unique code for each outlet |
| `Outlet Establishment Year` | Numeric | Year the outlet was opened (ranges from 2011–2022) |
| `Outlet Size` | Text | Size of the store — `Small`, `Medium`, `High` |
| `Outlet Location Type` | Text | City tier where the outlet is located — `Tier 1`, `Tier 2`, `Tier 3` |
| `Outlet Type` | Text | Store format — `Grocery Store`, `Supermarket Type1`, `Supermarket Type2`, `Supermarket Type3` |
| `Sales` | Numeric | Revenue generated by the item at that outlet |
| `Rating` | Numeric | Outlet/item performance rating (out of 5) |

**Note on data quality:** The `Item Fat Content` field has duplicate categories with inconsistent casing/abbreviation (`Low Fat`, `low fat`, `LF` all mean the same thing; `Regular` and `reg` also overlap). This should be cleaned before deeper analysis.

## 📊 Dashboard Walkthrough — Step by Step

The report is built from **11 distinct visuals** arranged across a filter panel, KPI cards, a tabbed chart cluster, and three standalone panels. Each one is broken down below in the order it appears on screen (left → right, top → bottom).

---

### STEP 1 — Filter Panel (far left, yellow sidebar)
**Visual type:** Slicers (dropdown filters)
**Fields used:** `Outlet Location Type`, `Outlet Size`, `Item Type`

| Slicer | Options | Purpose |
|---|---|---|
| Outlet Location Type | All / Tier 1 / Tier 2 / Tier 3 | Filters the whole report to a single city tier |
| Outlet Size | All / Small / Medium / High | Filters the whole report to a single store size |
| Item Type | All / any of the 16 categories | Filters the whole report to one product category |

These three slicers are **global** — changing any one of them updates every card, chart, and table on the page simultaneously (default state: all set to "All").

---

### STEP 2 — KPI Cards (top center row)
**Visual type:** 4 KPI/Card visuals
**Fields used:** `Sales` (sum & average), `Item Identifier` (count), `Rating` (average)

| Card | Value | Icon | Calculation |
|---|---|---|---|
| Total Sales | **$1.20M** | Bar-chart icon, green header | `SUM(Sales)` across all 8,523 rows |
| Avg Sales | **$141** | Small bar icon | `AVERAGE(Sales)` per item |
| Number of Item | **9K** | Package/box icon | `COUNT(Item Identifier)` → 8,523 rounded to nearest thousand |
| Avg Rating | **3.9** | Star icon | `AVERAGE(Rating)` across all outlets |

These four cards form the "headline" summary — the very first numbers a viewer sees before drilling into any chart.

### STEP 10 — Outlet Type Table (bottom right panel)
**Visual type:** Table/matrix with colored value pills
**Fields used:** `Outlet Type`, `Total_Sales`, `No_Of_Items`, `AVG_Sales`, `AVG_Rating`, `Item Visibility`

| Outlet Type | Total_Sales | No_Of_Items | AVG_Sales | AVG_Rating | Item Visibility |
|---|---|---|---|---|---|
| Supermarket Type2 | $131.48K | 928 | $142 | 3.9 | 56.62 |
| Supermarket Type3 | $130.71K | 935 | $140 | 3.9 | 54.80 |
| Grocery Store | $151.94K | 1,083 | $140 | 3.9 | 113.57 |
| Supermarket Type1 | **$787.55K** | **5,577** | $141 | 3.9 | 338.65 |

**Reading it column-by-column:**
- **Total_Sales:** Supermarket Type1 dwarfs the other three formats combined (~5x the next-largest).

- **AVG_Sales:** Nearly identical across all four formats ($140–$142) — meaning no format is "better" per item, they just differ in scale.
- **AVG_Rating:** Flat at 3.9 for all formats — customer satisfaction doesn't vary by store format.
- **Item Visibility:** Highest for Type1 (338.65) and Grocery Store (113.57), much lower for Type2/Type3 — suggesting shelf/display space also scales with store size.

### STEP 11 — Cross-Reading the Whole Dashboard
Putting Steps 1–10 together, the dashboard tells one consistent story:
- **Scale, not efficiency, drives BlinkIT's sales.** Average sales-per-item and average rating are nearly flat everywhere (Steps 2, 10) — the differences in total sales come entirely from *how many items/outlets* exist in each segment (Steps 6, 7, 9, 10).
- **Regular over low-fat, staples over specialty** — Fruits & Vegetables, Snack Foods, and Household goods dominate revenue (Steps 4–6).
- **Tier 3 and Medium-sized outlets** are the unsung leaders — outperforming the "premium" Tier 1/High-size segments (Steps 8–9).
- **2018 is an anomaly worth investigating** — it's the single sharpest deviation anywhere in the dashboard (Step 7).

---

## 🔍 Key Takeaways
1. **Regular** fat-content items outsell **Low Fat** items by a wide margin.
2. **Fruits & Vegetables** and **Snack Foods** are the top-selling categories; **Seafood** and **Breakfast** are the weakest.
3. Outlets established in **2018** dramatically outperform other years — worth investigating what changed that year (new format, new locations, etc.).
4. **Tier 3** locations outperform Tier 1 and Tier 2 in total sales, suggesting strong demand in smaller cities.
5. **Supermarket Type1** is the core revenue driver of the business, contributing the large majority of total sales through sheer item/outlet volume rather than higher per-item sales.
6. Average rating (3.9) and average sales (~$141) are **remarkably consistent** across outlet types and tiers — meaning performance issues are about reach/scale, not store quality.

## 🧮 Measures Used (DAX)

These are the calculated measures powering the KPI cards, charts, and table in the report. Written for Power BI's Data Model (based on the `Sales`, `Rating`, and `Item Identifier` fields in `BlinkIT_Grocery_Data.xlsx`).

### Core KPI Measures
```DAX
Total_Sales = SUM('BlinkIT_Grocery_Data'[Sales])

AVG_Sales = AVERAGE('BlinkIT_Grocery_Data'[Sales])

Number_Of_Items = COUNT('BlinkIT_Grocery_Data'[Item Identifier])

AVG_Rating = AVERAGE('BlinkIT_Grocery_Data'[Rating])
```

### Formatted / Display Versions
Used directly on the KPI cards where values are shown in K/M shorthand (e.g., "$1.20M", "9K"):
```DAX
Total_Sales_Display = 
DIVIDE([Total_Sales], 1000000) & "M"

Number_Of_Items_Display = 
DIVIDE([Number_Of_Items], 1000) & "K"
```

### Fat Content Split (Donut Chart — Step 4)
```DAX
Regular_Sales = 
CALCULATE([Total_Sales], 'BlinkIT_Grocery_Data'[Item Fat Content] IN {"Regular", "reg"})

Low_Fat_Sales = 
CALCULATE([Total_Sales], 'BlinkIT_Grocery_Data'[Item Fat Content] IN {"Low Fat", "low fat", "LF"})

Fat_Content_Cleaned = 
SWITCH(
    TRUE(),
    'BlinkIT_Grocery_Data'[Item Fat Content] IN {"Low Fat", "low fat", "LF"}, "Low Fat",
    'BlinkIT_Grocery_Data'[Item Fat Content] IN {"Regular", "reg"}, "Regular"
)
```
*(`Fat_Content_Cleaned` is a calculated column that standardizes the five inconsistent raw values into two clean categories — used as the legend field for the donut and the Fat-by-Outlet bar chart.)*

### Outlet Establishment Trend (Line Chart — Step 7)
```DAX
Sales_By_Establishment_Year = 
CALCULATE([Total_Sales], ALLEXCEPT('BlinkIT_Grocery_Data', 'BlinkIT_Grocery_Data'[Outlet Establishment Year]))
```

### Outlet Location Share Ribbon (Step 9)
```DAX
Tier2_Tier3_Share_% = 
DIVIDE(
    CALCULATE([Total_Sales], 'BlinkIT_Grocery_Data'[Outlet Location Type] IN {"Tier 2", "Tier 3"}),
    [Total_Sales]
)
```
*(This is the measure behind the "71.3%" ribbon label in Step 9 — Tier 2 + Tier 3 combined sales as a % of total sales.)*

### Outlet Size Donut Boundaries (Step 8)
```DAX
Sales_By_Outlet_Size = 
CALCULATE([Total_Sales], ALLEXCEPT('BlinkIT_Grocery_Data', 'BlinkIT_Grocery_Data'[Outlet Size]))
```

### Outlet Type Table (Step 10)
```DAX
Item_Visibility_Avg = 
AVERAGE('BlinkIT_Grocery_Data'[Item Visibility]) * 1000
```
*(Multiplied/scaled so values display as whole numbers like 338.65, 56.62, etc., matching the table.)*

### Rank / Sort Helper (used to sort Item Type bar chart descending — Step 6)
```DAX
Item_Type_Sales_Rank = 
RANKX(
    ALL('BlinkIT_Grocery_Data'[Item Type]),
    [Total_Sales],
    ,
    DESC
)
```

> ⚠️ **Note:** The original `.pbix` (Power BI project) file was not provided — only the raw `.xlsx` data and a dashboard screenshot. The DAX measures above are reconstructed to reproduce the exact figures visible in the screenshot (e.g., $1.20M, $141, 3.9, 71.3%) and should be verified/adjusted against your actual `.pbix` file if you have one.
